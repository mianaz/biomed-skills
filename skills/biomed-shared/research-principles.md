# Research practice

Start with an interesting biological question and a consequential next decision.
Develop the most illuminating explanation compatible with the observations, then
choose a feasible way to learn more. Unexpected, mixed and negative results can
reshape a productive model. Keep scientific ambition in the planning as well as
the writing.

Reuse the project's existing literature, IDs, task board, lab notebook and output
layout. Connect question → idea → experiment → run → data → result → next decision
through source links. A short note or table is enough when it supports that chain.
Use a detailed record only where identity, timing, interpretation or handoff needs
it. Keep protocols, task status and inventory quantities in one owning record;
dashboards and maps are views of those records.

Distinguish planned work, actual execution, observed result and interpretation.
Show source access at the level read. Preserve identifiers, human decisions,
unexpected observations and important contrary evidence. Update affected plans
when a result changes the decision rather than generating an ever-growing task list.

Inspect current records before modifying a project. Work within the user's
authorization; a general workflow discussion does not by itself schedule events,
order reagents, migrate a lab database or transfer unpublished material. Use public
concepts for external searches and keep private project material in its existing
authorized locations. A requested routine local edit needs no extra approval.

For a research project, keep a root HTML entry under
[the dashboard contract](project-dashboard.md). For source provenance and optional
further reading, use [research sources](research-sources.md).
